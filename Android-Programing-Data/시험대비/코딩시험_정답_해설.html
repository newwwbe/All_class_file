안드로이드 코딩 실기 정답 · 해설 (4~7장)

각 문제마다 핵심 개념 → 정답 코드 → 자주 틀리는 점 순서입니다. 문제 제목 아래 "화면 보기"를 누르면 실행 결과 그림으로 갑니다.

모든 문제 공통

  • package와 import는 생략했습니다. Android Studio에서 빨간 글자 위에 Alt+Enter를 누르면 import가 자동 추가돼요.
  • AlertDialog는 androidx.appcompat.app.AlertDialog를 import하세요. (android.app 쪽도 동작은 하지만 수업 기준은 androidx)
  • 새 Activity를 만들었다면 AndroidManifest.xml에 등록돼야 실행됩니다. 실행할 Activity에 <intent-filter>(MAIN + LAUNCHER)를 옮기세요.
  • switch (v.getId()) + case R.id.xxx:는 쓰지 마세요. 최신 Android Studio(AGP 8 이상)에서는 R.id 값이 상수가 아니라서 "Constant expression required" 오류가 납니다. 그래서 이 해설은 전부 if / else if로 썼습니다.
  • 리스너 안(익명 클래스)에서 this는 Activity가 아니라 리스너 자신입니다. Context가 필요하면 MainActivity.this처럼 클래스명.this 또는 getApplicationContext()를 쓰세요.

문제 1. 위젯 속성으로 화면 꾸미기 ★

화면 보기 →

핵심 개념

· 버튼 배경색이 안 바뀌고 보라색이면 Material 테마 때문. android:backgroundTint="#00ff00"로 바꾸면 됩니다.

문제 2. 초간단 계산기 ★★

화면 보기 →

핵심 개념

  • inputType="numberDecimal": 숫자 키패드 + 소수점만 입력 가능.
  • EditText 값은 getText().toString()으로 문자열 → Double.parseDouble()로 실수 변환.
  • 버튼 5개가 리스너 하나를 공유하고 v == btnAdd처럼 어떤 버튼인지 구분하면 코드가 짧아집니다.
  • 왜 0 검사가 필요한가: double은 0으로 나눠도 앱이 안 죽고 Infinity, NaN이 찍혀요. 그래서 직접 막아야 합니다.
자주 틀리는 점
· Integer.parseInt()를 쓰면 "실수 계산" 조건 위반이고, 3.5 같은 값에서 앱이 죽습니다.
· 빈 칸 검사를 parseDouble보다 먼저 해야 합니다. 순서가 바뀌면 빈 문자열 변환에서 앱이 죽어요.
· String.format("%.1f")는 반올림합니다(2/3 → 0.7). 같은 결과를 Math.round(x * 10) / 10.0으로도 낼 수 있어요.
· 교재처럼 버튼마다 리스너를 따로 만들어도 정답입니다. 단, 계산식만 다르고 검사 코드는 5번 반복돼요.

문제 4. gravity와 layout_gravity ★

화면 보기 →

핵심 개념

  • 표의 "버튼 위치" 열 = layout_gravity, "글자 위치" 열 = gravity. 이 문제는 이 구분 하나만 묻습니다.
  • 두 방향을 합칠 땐 |: "right|top" = 오른쪽 위.
  • 세로 LinearLayout 안에서 layout_gravity는 가로 위치만 의미 있어요 (세로는 순서대로 쌓이니까).
자주 틀리는 점
· center_vertical(세로 가운데)과 center(가로+세로 가운데)는 다릅니다. 버튼2는 "왼쪽 가운데"라 left|center_vertical.
· 빨간색을 #FF0000으로 직접 쓰면 "colors.xml 등록" 조건 위반.
· 빨간 배경이 안 보이면 문제 1과 같은 Material 테마 문제 → android:backgroundTint="@color/red".

문제 5. 중첩 LinearLayout과 weight ★★

화면 보기 →

핵심 개념

  • layout_weight: 남은 공간을 비율로 나눔. 모두 1이면 똑같이.
  • 나누는 방향의 크기를 0dp로: 세로로 나누면 layout_height="0dp", 가로로 나누면 layout_width="0dp". 이렇게 해야 정확히 같은 비율이 됩니다.
  • "세로 안에 가로, 가로 안에 세로"로 상자를 쪼개 나간다고 생각하면 쉬워요.
자주 틀리는 점
· 바깥 레이아웃에 orientation을 빼먹으면 기본값이 horizontal이라 위/아래가 아니라 좌/우로 나뉩니다.
· 0dp 대신 match_parent에 weight를 주면 비율이 거꾸로 나오는 등 이상해질 수 있어요.
· Java는 setContentView(R.layout.prob05_main)만 있으면 됩니다.

문제 6. RelativeLayout 버튼 배치 ★★

화면 보기 →

핵심 개념

  • RelativeLayout은 다른 위젯 기준으로 위치를 정함: layout_toLeftOf(~의 왼쪽), layout_toRightOf(~의 오른쪽), layout_below(~의 아래).
  • 부모 기준은 layout_alignParentRight="true" 같은 형태.
  • "아래 + 왼쪽"처럼 두 조건을 같이 주면 대각선 계단 모양이 됩니다.
자주 틀리는 점
· @id/btnCancel은 이미 위에서 선언된 id를 참조할 때. 아직 선언 전인 id를 참조하려면 @+id/를 써야 합니다.
· layout_below만 쓰면 왼쪽 끝으로 붙어버려요. 가로 기준(toLeftOf/toRightOf)도 꼭 같이.
· layout_alignParentRight, layout_toLeftOf는 RelativeLayout 안에서만 동작합니다. LinearLayout 안에 쓰면 무시돼요.

문제 7. XML 없이 Java 코드로 화면 만들기 ★★★

화면 보기 →

핵심 개념

  • XML 태그 하나 = Java의 new 위젯(this) 하나. XML 속성 = setXxx() 메서드.
  • 크기는 LayoutParams 객체로 전달, 자식 추가는 addView().
  • setContentView(레이아웃, params): R.layout 대신 직접 만든 레이아웃 객체를 넘김.
자주 틀리는 점
· setContentView(R.layout.xxx)를 쓰면 바로 오답. 이 문제는 XML 금지예요.
· addView()를 빼먹으면 위젯을 만들어도 화면에 안 나옵니다. 추가한 순서대로 위에서 아래로 쌓여요.
· 리스너 안에서 쓰는 지역변수(edt, tv)는 final이어야 합니다 (값을 다시 안 바꾸면 생략해도 됨).
· setTextSize(20)의 단위는 기본 sp입니다.

문제 8. 날짜/시간 예약 앱 ★★★

· getCurrentHour()에 줄이 그어져도(deprecated) 동작합니다. 최신 방식은 getHour(), getMinute().

문제 10. 간단 웹 브라우저 ★★★

화면 보기 →

핵심 개념

문제 14. 컨텍스트 메뉴 + 선택 대화상자 ★★★

화면 보기 →

핵심 개념

  • 컨텍스트 메뉴(길게 누르기) 3단계: registerForContextMenu(위젯) 등록 → onCreateContextMenu에서 메뉴 만들기 → onContextItemSelected에서 처리.
  • 위젯마다 다른 메뉴: onCreateContextMenu의 v가 길게 눌린 위젯이라 v == button1으로 구분.
  • 라디오 목록 대화상자: setSingleChoiceItems(배열, 처음 선택 위치, 리스너), which가 고른 번호.
자주 틀리는 점
· registerForContextMenu()를 빼면 길게 눌러도 아무 일도 안 일어납니다.
· onCreateContextMenu, onContextItemSelected는 onCreate 바깥, 클래스 안에 따로 씁니다(오버라이드 메서드). Android Studio에서 Ctrl+O로 넣으면 편해요.
· setSingleChoiceItems의 두 번째 인자 0은 "Q가 처음부터 선택됨". 아무것도 선택 안 된 상태로 열려면 -1.
· "2배 확대"는 교재처럼 setScaleX(2)(가로만)로 썼습니다. 세로도 키우려면 setScaleY(2) 추가.
· menu2/menu3의 id를 문제 11 menu1과 같은 이름(subSize 등)으로 지으면 한 프로젝트 안에서 헷갈리니 다른 이름을 쓰세요.
