# 모바일프로그래밍 11/16 — 9장 레이아웃 (예제 41~42)

| 번호 | 내용 | 위젯 |
|---|---|---|
| 41 | 리니어레이아웃1 안에 리니어레이아웃 3개 배치 (화면 3등분) | TextView, LinearLayout 3 |
| 42 | 화면 분할 (작년 중간·기말 시험 문제) | TextView, LinearLayout 6 |

## 레이아웃이란
- **위젯들을 배치해서 화면을 구성하는 틀** (위젯 = 화면을 구성하는 요소, 윈도우의 아이콘 같은 것)
- 종류: 리니어, 렐러티브, 프레임, 테이블, 그리드
  - 렐러티브: 새 프로젝트의 기본값이지만 잘 안 씀
  - 그리드: 게임 만들 때 말고는 잘 안 씀
  - **수업에서 배우는 3가지: 리니어, 프레임, 테이블**

## 리니어 레이아웃
- 위젯을 **좌측 상단부터 위에서 아래로 차례차례** 배치 (한 줄에 하나씩, 선형)
- 지금까지(1~40번) 대부분의 실습에서 사용
- 그래서 버튼을 한 줄에 여러 개(계산기처럼) 넣을 수 없었음

## 41번 구조
```
리니어레이아웃1 (바깥 배경, fill_parent, vertical)
├─ TextView
├─ 리니어레이아웃2 (노랑)
├─ 리니어레이아웃3 (빨강)
└─ 리니어레이아웃4 (파랑)
```
- 2·3·4는 **서로 영역을 침범할 수 없는 독립적인 공간**
- 바깥 테두리(리니어레이아웃1) 없이 2·3·4만 둘 수는 없음

## 속성
- `layout_width`: 가로 폭, `layout_height`: 세로 높이
- `layout_weight`: 가중치. 1:1:1이면 3명이 3분의 1씩 나눠 가짐
- **화면을 등분하려면 `layout_height`를 `wrap_content`가 아니라 `match_parent`로, `layout_weight`는 1로**
- `background`: 배경색. 네이버에서 "색상 코드표" 검색해서 `#FFFF00` 같은 코드 복사

## 이클립스 팁
- 레이아웃 입력: `<` 다음 **Shift + L**(대문자)로 LinearLayout 자동완성
- 태그 왼쪽 **`-` 기호로 접어두기**, `+`로 펼치기 (레이아웃이 많을 때 덜 헷갈림)
- 그래픽 레이아웃으로 구조 확인 가능, 화면 호환 문제가 있을 수 있으니 에뮬레이터도 켜두기

> 41번 색깔은 강의에서 "노란색 계통, 붉은색 계통"만 언급되어 노랑/빨강/파랑으로 임의 지정.

## 42번 구조 (작년 시험 문제)
```
┌───────────┬───────────┐
│           │    3-1    │
│  2 (왼쪽)  ├───────────┤
│           │    3-2    │
├───────────┴───────────┤
│           4           │
└───────────────────────┘
```
분할 순서 (교수님 방식): **전체를 생각하지 말고 한 단계씩 나눈다**
1. 리니어레이아웃1(vertical)을 **위 2 / 아래 4** 로 수직 등분
2. 위의 2(노랑)를 **horizontal** 로 바꿔 **왼쪽(빨강) / 오른쪽 3(파랑)** 으로 수평 등분
3. 오른쪽 3을 **vertical** 로 **3-1(초록) / 3-2(핑크)** 로 수직 등분

```
리니어레이아웃1 (vertical)
├─ TextView
├─ 리니어레이아웃2 (노랑, horizontal)
│   ├─ 2 왼쪽 (빨강)
│   └─ 리니어레이아웃3 (파랑, vertical)
│       ├─ 3-1 (초록)
│       └─ 3-2 (핑크)
└─ 리니어레이아웃4 (회색)
```
- **위아래로 나누면 수직(vertical), 옆으로 나누면 수평(horizontal)** → 나눌 대상을 감싸는 레이아웃의 `orientation` 을 바꾼다
- 등분하는 방향의 크기를 `match_parent` + `weight 1`
  - 좌우 등분: `layout_width="match_parent"`, 위아래 등분: `layout_height="match_parent"`
- 번호는 보기 편하라고 붙인 것. 순서가 달라도(2·3을 먼저 나누고 4를 나중에) 구조만 맞으면 됨
- **리니어레이아웃은 또 다른 리니어레이아웃을 포함하고, 포함된 레이아웃 바깥에는 또 다른 레이아웃이 있다**
- 헷갈리면 배경색을 칠해서 그래픽 레이아웃으로 확인
- 시험에 레이아웃 문제가 1~3개 나옴. 구조가 머릿속에 잡히면 금방 풀지만 아니면 시간이 오래 걸려 점수가 낮은 영역

> 42번 색깔: 노랑·빨강·파랑·초록·핑크는 강의에서 언급. 4번 색은 알아듣기 어려워 회색으로 지정.
> 2의 노랑은 왼쪽(빨강)과 3(파랑)에 덮여서 화면에는 보이지 않음.

## 렐러티브 레이아웃 (시험 X, 필기만)
- 레이아웃 안의 위젯을 **상대적인 위치**로 배치. 게임(바둑·장기) 캐릭터 이동에 주로 사용
- 속성은 `true` / `false` 값
  - `layout_alignParentLeft` 왼쪽, `layout_alignParentRight` 오른쪽
  - `layout_alignParentTop` 위, `layout_alignParentBottom` 아래
  - `layout_centerHorizontal` 수평 중앙, `layout_centerVertical` 수직 중앙
  - `layout_centerInParent` 정중앙
- `layout_` 다음 `a` 치면 align, `c` 치면 center 목록이 나옴

## 프레임 레이아웃 (시험에서 배점이 제일 큼)
- **화면을 여러 개 만들고 중첩시켜서 한 번에 하나씩 보이게** 하는 형태 (책 페이지처럼)
  - 예: 레벨1 화면 → 레벨2 화면 → 레벨3 화면 순서대로 바뀜
- 각 화면은 리니어, 테이블 등 **서로 다른 종류의 레이아웃**도 될 수 있음
- 각 화면은 **독립적으로 실행**
- 작년에는 5명 중 3명이 패스할 만큼 어려워한 부분
